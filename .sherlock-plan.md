## 1. Goal & Scope

Add Supabase auth to clipcal and migrate ALL app data (flyer events, profile, interests, relevance scores) from client-localStorage to Supabase Postgres with Row-Level Security.

**Hard gate:** no anonymous use. Every page requires an authenticated `@umn.edu` user.

**Auth methods (v1):** email+password, magic link, Google OAuth — all restricted to `@umn.edu`.

- `middleware.ts` for session refresh + route protection (NOT `proxy.ts` — that has an open production bug with Cloudflare per vercel/next.js#86122; codemod to `proxy.ts` later)

- Docs updates: `README.md`, `docs/brief.md`, `CHANGELOG.md`, `release_notes.md`, new ADR

## 2. Architecture Decision

### Summary
**Minimal + hybrid.** Browser `@supabase/ssr` client talks directly to Postgres for all CRUD (RLS enforces ownership). Existing `app/api/*` LLM-compute routes stay, gain a server-side `auth.getUser()` gate at the top, and re-key rate limits from IP to `user.id`.

### Rationale
Per deep-r research:
1. RLS is mandatory on every table regardless. Adding a REST-wrapper tier would duplicate enforcement at the route handler, costing LOC without adding safety.
2. The existing `app/api/*` routes are LLM compute, not CRUD. Inventing a new CRUD REST layer has no existing surface to mirror.
3. Hackathon-demo horizon — fewer layers = faster to build and debug.
4. `@supabase/ssr` is Supabase's documented, supported pattern for Next.js App Router.

### Approach chosen
- **CRUD (new, replaces localStorage):** `createBrowserClient` in client components, direct `supabase.from(...)` calls, RLS does authorization.
- **LLM compute (existing `app/api/*`):** `createServerClient` at top of each route, `await supabase.auth.getUser()` — reject 401 if absent. Rate-limit key: `user.id`.
- **Session refresh:** `middleware.ts` at repo root calls `supabase.auth.getUser()` on every request; redirects unauthenticated users from protected paths to `/login`. Matcher explicitly excludes `/login`, `/auth/callback`, `/auth/signout`, and static assets to avoid redirect loops.
- **Service-role key:** used ONLY inside `app/api/relevance/route.ts` to write `relevance_cache` (scoring is LLM-derived trust data — server-only writes). Never shipped client-side.

### Rejected alternatives
- **Clean (Server Actions for writes):** more idiomatic Next 16 but doubles the code to write and maintain, for no security benefit over RLS. Good future migration path; unnecessary now.
- **Pragmatic (wrap all CRUD in new `/api/*` routes):** most ceremony, least benefit, invents a layer we don't have.

### Trade-offs named
- **RLS bugs are silent.** Policies that return zero rows look like empty state. Mitigation: mandatory pgTAP negative tests (§6) run in CI before every deploy.
- **Anon key ships to client** — by design, scoped by RLS. Document in `SECURITY.md`.
- **Lose cross-cutting hooks** (centralized logging per write). Acceptable for demo; revisit if we promote.

## 3. Data Model & Schema

### Entity-Relationship
```
auth.users (Supabase-managed)
    │  id (uuid)
    │
    ├──── profiles (1:1)          one row per user; user's self-description
    │       user_id PK/FK
    │
    ├──── event_batches (1:N)     one row per flyer upload
    │       id PK, user_id FK
    │       │
    │       └──── events (1:N)    events extracted from a single batch
    │               id PK, batch_id FK, user_id FK (denormalized for RLS)
    │
    └──── relevance_cache (N)     per-user per-event hash
            (user_id, event_hash) PK
```

Why `user_id` denormalized onto `events`: simpler, faster RLS (`user_id = auth.uid()` direct, no join). The cost is one redundant column.

### Migration: `supabase/migrations/0001_init_schema.sql`

```sql
-- =========================================================================
-- PROFILES
-- =========================================================================
create table public.profiles (
  user_id          uuid primary key references auth.users(id) on delete cascade,
  major            text,
  stage            text check (stage in ('freshman','sophomore','junior','senior','grad')),
  interests        text[] not null default '{}',
  show_tradeoffs   boolean not null default true,
  surface_noticings boolean not null default true,
  vibe             text,
  profile_version  bigint not null default 1,    -- server-managed (REVOKE UPDATE below); bumped by trigger
  created_at       timestamptz not null default now(),
  updated_at       timestamptz not null default now()
);
alter table public.profiles enable row level security;

-- Auto-bump profile_version on any change to scoring-relevant fields.
-- Also DEFENSIVELY resets client-supplied profile_version and updated_at —
-- column-level REVOKE below is the primary gate, but this is belt+suspenders.
create or replace function public.bump_profile_version() returns trigger
language plpgsql
security definer set search_path = '' as $$
begin
  -- Lock server-managed columns to OLD values first, then conditionally bump.
  new.profile_version := coalesce(old.profile_version, 1);
  new.created_at      := old.created_at;
  if new.major       is distinct from old.major
     or new.stage    is distinct from old.stage
     or new.interests is distinct from old.interests
     or new.vibe     is distinct from old.vibe then
    new.profile_version := coalesce(old.profile_version, 1) + 1;
  end if;
  new.updated_at := now();
  return new;
end; $$;
create trigger profiles_bump_version before update on public.profiles
  for each row execute function public.bump_profile_version();

-- Seed a profiles row on first signup.
-- search_path='' + fully-qualified references = hardened against search_path hijacking.
create or replace function public.handle_new_user() returns trigger
language plpgsql
security definer set search_path = '' as $$
begin
  insert into public.profiles (user_id) values (new.id) on conflict do nothing;
  return new;
end; $$;
create trigger on_auth_user_created after insert on auth.users
  for each row execute function public.handle_new_user();

-- C1 fix: server-managed columns are NOT client-writable via PostgREST.
-- RLS WITH CHECK cannot reference OLD, so column-level REVOKE is the canonical gate.
revoke update (profile_version, created_at, updated_at) on public.profiles from authenticated;
grant  update (major, stage, interests, show_tradeoffs, surface_noticings, vibe)
       on public.profiles to authenticated;

-- RLS: users own their profile; INSERT blocked (trigger seeds it).
create policy "profiles_select_own" on public.profiles
  for select to authenticated
  using ( (select auth.uid()) is not null and (select auth.uid()) = user_id );

create policy "profiles_update_own" on public.profiles
  for update to authenticated
  using      ( (select auth.uid()) = user_id )
  with check ( (select auth.uid()) = user_id );

-- No INSERT policy = clients cannot insert; trigger does it.
-- No DELETE policy = cascade from auth.users is the only deletion path.

-- =========================================================================
-- EVENT_BATCHES
-- =========================================================================
create table public.event_batches (
  id             uuid primary key default gen_random_uuid(),
  user_id        uuid not null references auth.users(id) on delete cascade,
  source_notes   text,
  ics_committed  boolean not null default false,
  added_at       timestamptz not null default now()
);
alter table public.event_batches enable row level security;
create index event_batches_user_idx on public.event_batches (user_id, added_at desc);

create policy "batches_select_own" on public.event_batches
  for select to authenticated
  using ( (select auth.uid()) = user_id );
create policy "batches_insert_own" on public.event_batches
  for insert to authenticated
  with check ( (select auth.uid()) = user_id );
create policy "batches_update_own" on public.event_batches
  for update to authenticated
  using      ( (select auth.uid()) = user_id )
  with check ( (select auth.uid()) = user_id );
create policy "batches_delete_own" on public.event_batches
  for delete to authenticated
  using ( (select auth.uid()) = user_id );

-- =========================================================================
-- EVENTS
-- =========================================================================
create table public.events (
  id              uuid primary key default gen_random_uuid(),
  batch_id        uuid not null references public.event_batches(id) on delete cascade,
  user_id         uuid not null references auth.users(id) on delete cascade,  -- denormalized
  title           text not null,
  starts_at       timestamptz not null,
  ends_at         timestamptz,
  location        text,
  description     text,
  category        text not null check (category in
    ('workshop','networking','social','cs','career','culture','sports','hackathon','other')),
  has_free_food   boolean not null default false,
  timezone        text not null default 'America/Chicago',
  confidence      text not null check (confidence in ('high','medium','low')),
  venue_setting   text,
  crowd_size      text,
  created_at      timestamptz not null default now()
);
alter table public.events enable row level security;
create index events_user_starts_idx on public.events (user_id, starts_at);
create index events_batch_idx       on public.events (batch_id);

-- Constraint: denormalized user_id must match parent batch's user_id.
-- Enforced by WITH CHECK below AND by trigger (belt+suspenders).
create or replace function public.events_enforce_user_match() returns trigger
language plpgsql
security definer set search_path = '' as $$
declare batch_user uuid;
begin
  select user_id into batch_user from public.event_batches where id = new.batch_id;
  if batch_user is null or batch_user <> new.user_id then
    raise exception 'events.user_id must match parent batch.user_id';
  end if;
  return new;
end; $$;
create trigger events_user_match before insert or update on public.events
  for each row execute function public.events_enforce_user_match();

create policy "events_select_own" on public.events
  for select to authenticated
  using ( (select auth.uid()) = user_id );
create policy "events_insert_own" on public.events
  for insert to authenticated
  with check ( (select auth.uid()) = user_id );
create policy "events_update_own" on public.events
  for update to authenticated
  using      ( (select auth.uid()) = user_id )
  with check ( (select auth.uid()) = user_id );
create policy "events_delete_own" on public.events
  for delete to authenticated
  using ( (select auth.uid()) = user_id );

-- =========================================================================
-- RELEVANCE_CACHE
-- =========================================================================
create table public.relevance_cache (
  user_id          uuid not null references auth.users(id) on delete cascade,
  event_hash       text not null,                    -- SHA-256 hex of normalized (title|starts_at|location)
  score            smallint not null check (score between 0 and 100),
  reason           text,
  model_version    text not null,                     -- e.g. 'claude-haiku-4-5@2025-10'
  profile_version  bigint not null,                    -- snapshot at compute time; must match profiles.profile_version for a cache hit
  created_at       timestamptz not null default now(),
  updated_at       timestamptz not null default now(),
  expires_at       timestamptz not null default now() + interval '7 days',   -- shorter than profile_version invalidation for belt+suspenders
  primary key (user_id, event_hash)
);
alter table public.relevance_cache enable row level security;
create index relevance_cache_expires_idx      on public.relevance_cache (expires_at);
create index relevance_cache_user_version_idx on public.relevance_cache (user_id, profile_version);

-- Clients read only. All writes go through service_role in /api/relevance.
create policy "relevance_cache_select_own" on public.relevance_cache
  for select to authenticated
  using ( (select auth.uid()) = user_id );
-- NO insert/update/delete policies for authenticated. service_role bypasses RLS.

-- =========================================================================
-- UMN DOMAIN ENFORCEMENT (Before User Created Hook target)
-- =========================================================================
create or replace function public.enforce_umn_domain(event jsonb)
returns jsonb
language plpgsql
security definer set search_path = ''
as $$
declare
  email_addr text := lower(trim(event->'user'->>'email'));
  provider   text := event->'user'->'app_metadata'->>'provider';
  domain_err jsonb := jsonb_build_object(
    'error', jsonb_build_object(
      'http_code', 400,
      'message', 'Only @umn.edu email addresses are allowed.'
    )
  );
begin
  -- Reject null/empty, control characters, trailing dots.
  if email_addr is null
     or email_addr = ''
     or email_addr ~ '[[:cntrl:]]'
     or right(email_addr, 1) = '.' then
    return domain_err;
  end if;

  -- W6: unambiguous domain equality (no regex semantics to trip on).
  if split_part(email_addr, '@', 2) <> 'umn.edu' then
    return domain_err;
  end if;

  -- C4: only trust email as "verified" for providers that verify it server-side.
  -- Google ID tokens only carry email_verified=true. Password/magic-link users
  -- must pass Supabase's own "Confirm email" flow (enabled in project settings).
  -- Any other OAuth provider is rejected here until explicitly allowlisted.
  if provider is null or provider not in ('email', 'google') then
    return jsonb_build_object(
      'error', jsonb_build_object(
        'http_code', 400,
        'message', 'Unsupported auth provider.'
      )
    );
  end if;

  return '{}'::jsonb;
end;
$$;
grant execute on function public.enforce_umn_domain to supabase_auth_admin;
revoke execute on function public.enforce_umn_domain from authenticated, anon, public;
```

**Key schema decisions:**
1. **`user_id` denormalized on `events`** — faster RLS, enforced by trigger to prevent drift.
2. **Profile is auto-seeded** by `on_auth_user_created` trigger; clients cannot INSERT (no INSERT policy).
3. **Relevance cache is SELECT-only for clients.** Server-side writes via service_role client in `/api/relevance`. Score integrity must not be client-controllable.
4. **`profile_version` auto-bumps** on meaningful profile edits; stale cache rows are read-filtered, reaped by a simple periodic delete (out of scope for v1 — rows expire via `expires_at`).
5. **ALL `auth.uid()` calls wrapped in `(select ...)`** — 95%+ perf improvement per Supabase benchmarks (research cites 179ms → 9ms on a benchmark dataset).
6. **Explicit `auth.uid() IS NOT NULL` guard on SELECT policies** — defensive clarity-of-intent.
7. **Column-level REVOKE on server-managed columns** (C1) — `profile_version`, `created_at`, `updated_at` on `profiles` are not `authenticated`-writable via PostgREST. RLS `WITH CHECK` cannot reference OLD, so REVOKE is the canonical pattern.
8. **All SECURITY DEFINER functions use `SET search_path = ''`** (C5) with fully-qualified references — prevents search-path hijacking via a malicious same-named object in a writable schema.
9. **Domain hook uses `split_part` for exact domain equality** (W6), not regex — unambiguous, no regex-flag footgun. Explicitly rejects trailing dots, control characters, and non-allowlisted auth providers (C4).

## 5. Acceptance Criteria (Given/When/Then)

These drive the RED phase. Every AC must map to at least one test before GREEN starts.

### Auth — Domain restriction
- **AC-1 (happy):** *Given* a user submits email `alice@umn.edu` with a valid password, *when* signup is triggered, *then* a row is created in `auth.users` and the Before-User-Created hook returns `{}`.
- **AC-2 (block):** *Given* a user submits `bob@gmail.com`, *when* signup is triggered, *then* the hook returns HTTP 400 `"Only @umn.edu email addresses are allowed."` and no row is created in `auth.users`.
- **AC-3 (Google OAuth):** *Given* a user signs in with Google using a non-`@umn.edu` account, *when* the callback runs, *then* the hook rejects creation even though the user got past Google's `hd=umn.edu` picker via URL manipulation.
- **AC-4 (magic link timing):** *Given* a new user requests a magic link with `eve@gmail.com`, *when* the request hits Supabase, *then* the rejection occurs BEFORE the magic-link email is dispatched.

### Auth — Account linking
- **AC-5:** *Given* user `alice@umn.edu` signs up with password AND confirms email, *when* she later clicks "Sign in with Google" with the same address, *then* a single `auth.users` row exists with two `auth.identities` rows (email + google) pointing at the same `user_id`.

### Auth — Route gating
- **AC-6:** *Given* an unauthenticated visitor, *when* they request `/`, `/feed`, or `/profile`, *then* `middleware.ts` redirects to `/login`. The middleware matcher excludes `/login`, `/auth/callback`, `/auth/signout`, and static assets so no redirect loop occurs.
- **AC-7:** *Given* an unauthenticated visitor, *when* they POST to any `app/api/*` route, *then* the handler returns 401.

### RLS — Events
- **AC-8 (own read):** *Given* Alice has 3 events, *when* Alice calls `supabase.from('events').select()`, *then* she sees exactly 3 rows.
- **AC-9 (cross-user block):** *Given* Bob has 5 events and Alice has 3, *when* Alice calls select, *then* she sees 3 rows (not 8).
- **AC-10 (cross-user insert block):** *Given* Alice is authenticated, *when* she INSERTs an event row with `user_id = bob_id`, *then* RLS `WITH CHECK` rejects the insert.
- **AC-11 (cross-user update block):** *Given* Alice owns a row, *when* she UPDATEs it to set `user_id = bob_id`, *then* RLS `WITH CHECK` rejects.
- **AC-12 (anon block):** *Given* a request with no JWT, *when* it SELECTs events, *then* zero rows are returned.
- **AC-13 (batch-events user-id match):** *Given* a batch owned by Alice, *when* anyone INSERTs an event with `batch_id=alice_batch, user_id=bob`, *then* the trigger raises.

### RLS — Profiles / batches / relevance_cache
- **AC-14:** `profiles` — one row auto-created on `auth.users` INSERT (via `handle_new_user` trigger); SELECT only own; UPDATE only own; INSERT and DELETE blocked.
- **AC-15:** `event_batches` — same pattern as events (AC-8..12) for all four CRUD ops.
- **AC-16:** `relevance_cache` — SELECT own works; INSERT/UPDATE/DELETE from `authenticated` role fails (no policy); service_role can upsert.

### Data persistence
- **AC-17 (batch upload):** *Given* Alice uploads a flyer, *when* `/api/extract` completes, *then* one row exists in `event_batches` with `user_id=alice_id` AND N rows in `events` all with `user_id=alice_id, batch_id=<new>`.
- **AC-18 (profile save):** *Given* Alice picks interests, *when* `saveProfile` runs, *then* `profiles.interests` is updated AND `profile_version` increments.
- **AC-19 (ICS committed flag):** *Given* Alice downloads ICS for a batch, *when* `markBatchCommitted(id)` runs, *then* `event_batches.ics_committed = true`.

### Relevance cache
- **AC-20 (cache miss):** *Given* Alice views event X for the first time, *when* `/api/relevance` is called, *then* Claude is invoked AND a `relevance_cache` row is upserted with `(alice_id, sha256(title|starts_at|location))`.
- **AC-21 (cache hit):** *Given* Alice has a cached score for event X, *when* `/api/relevance` is called again with the same event AND the same `profile_version`, *then* Claude is NOT invoked and the cached score is returned.
- **AC-22 (profile change invalidation):** *Given* Alice has cached scores, *when* her `profile_version` increments, *then* subsequent reads bypass the cache (because `WHERE profile_version = $current` filters them out).
- **AC-23 (hash stability):** *Given* the same event with trivial whitespace/case differences, *when* hashed, *then* produces the same `event_hash`.

### Rate limiting
- **AC-24:** *Given* Alice has authenticated, *when* she exceeds the per-user limit on `/api/extract`, *then* she receives 429 (keyed by `user.id`, not IP).

### Observability
- **AC-25:** No request logs include email addresses or any PII beyond `user.id` (UUID).

### Red-team additions (Step 4.5)
- **AC-26 (C1 — client cannot forge profile_version):** *Given* an authenticated Alice, *when* she PATCHes `profiles` with `{profile_version: 999}` via PostgREST, *then* PostgREST returns 403 (column-level REVOKE) AND/OR the trigger silently resets to OLD. Her actual `profile_version` is unchanged.
- **AC-27 (C3 — /api/relevance user_id source):** *Given* a POST to `/api/relevance` whose body contains `user_id: <bob_id>`, *when* the route runs, *then* the cache upsert uses the `user_id` from `auth.getUser()` (Alice), NOT from the body. Verified by unit test with a spy on the admin client.
- **AC-28 (W3 — logout flow):** *Given* an authenticated user POSTs to `/auth/signout`, *when* the route completes, *then* `supabase.auth.signOut()` has run, auth cookies are cleared from the response, and the user lands on `/login`. A subsequent request to `/` redirects to `/login`.
- **AC-29 (W5 — session expiry mid-session):** *Given* a user's access token has just expired, *when* they load a protected page, *then* middleware's `getUser()` call transparently refreshes via the refresh token cookie; the user is not logged out.
- **AC-30 (W5 — model_version invalidation):** *Given* Alice has a cached score for event X stamped with `model_version='claude-haiku-4-5@2025-10'`, *when* `/api/relevance` is called with the current model set to `'claude-haiku-4-5@2025-12'`, *then* the cache row is bypassed and re-computed (read query filters by current `model_version`).
- **AC-31 (W5 — concurrent batch inserts):** *Given* Alice has two tabs open and uploads a flyer in each simultaneously, *when* both `/api/extract` calls complete, *then* two distinct `event_batches` rows exist, both owned by Alice, no deadlock or unique-constraint violation.
- **AC-32 (W5 — OAuth callback failure):** *Given* the `/auth/callback` code exchange throws (e.g., network error, invalid code), *when* the route runs, *then* the user is redirected to `/login?error=oauth_callback_failed` with a visible error message — not a blank 500.
- **AC-33 (C4 — unknown OAuth provider rejected):** *Given* a user signs in via a hypothetical future provider not in the allowlist (`email`, `google`), *when* the hook fires, *then* signup is rejected with HTTP 400 "Unsupported auth provider."
- **AC-34 (W6 — domain regex edge cases):** *Given* signup emails `alice@umn.edu.evil.com`, `alice@umn.edu.`, `alice@UMN.EDU`, `alice@sub.umn.edu`, *when* the hook fires, *then* only `alice@UMN.EDU` (which normalizes to `alice@umn.edu`) is accepted; the other three are rejected.

### API route contracts (changes)

All seven `app/api/*` routes:
- New failure mode: **401 `{error: "unauthorized"}`** if `auth.getUser()` returns no user.
- Rate-limit key switches from `request IP` to `user.id`.
- Request/response shapes otherwise unchanged.

`/api/relevance` new internals:
1. `auth.getUser()` → user. **The `user.id` from here is the ONLY source of truth for `user_id` in every subsequent DB operation. NEVER read `user_id` from the request body** (C3).
2. Read current `profile_version` from `profiles` for `user.id` (single query; could be cached per-request).
3. For each event: compute `eventHash(event)`, SELECT from cache with filter `user_id = <user.id> AND event_hash = <h> AND profile_version = <current> AND model_version = <current> AND expires_at > now()`.
4. Cache hits: return cached score/reason. No Claude call.
5. Cache misses: call Claude as today.
6. Upsert results into `relevance_cache` using `createSupabaseAdminClient()` (service_role) — with `user_id` from step 1, `profile_version` from step 2, `model_version` from current config, `event_hash` from step 3.
7. Response shape identical to today.

## 7. RLS Correctness Checklist

Applied to every table. Verified by pgTAP tests.

### Structural
- [ ] `ENABLE ROW LEVEL SECURITY` in migration
- [ ] `SUPABASE_SERVICE_ROLE_KEY` referenced only in `lib/supabase/admin.ts` (grep-auditable)
- [ ] No `NEXT_PUBLIC_` prefix on service role key
- [ ] No views on these tables (if added later: `WITH (security_invoker = true)`)
- [ ] `SECURITY DEFINER` helpers (`handle_new_user`, `enforce_umn_domain`, `bump_profile_version`, `events_enforce_user_match`) have `SET search_path = ''` (empty) with fully-qualified references (`public.profiles`, `auth.users`) — prevents search-path hijacking. Not exposed via PostgREST.
- [ ] Column-level REVOKE in place for every server-managed column (`profile_version`, `created_at`, `updated_at` on profiles — C1)
- [ ] ESLint `no-restricted-imports` rule prevents accidental imports of `lib/supabase/admin` outside allowlisted paths (N5)

### Policies
- [ ] Every command (SELECT/INSERT/UPDATE/DELETE) has explicit allow or explicit deny (= no policy)
- [ ] Every policy scoped with `TO authenticated`
- [ ] `auth.uid()` wrapped in `(select ...)` everywhere
- [ ] SELECT policies include `auth.uid() IS NOT NULL` guard
- [ ] INSERT policies use `WITH CHECK`, never `USING`
- [ ] UPDATE policies have BOTH `USING` and `WITH CHECK` (and matching SELECT)
- [ ] No use of `user_metadata` (`raw_user_meta_data`) for authorization
- [ ] `current_user` never used — only `auth.uid()`

### Performance
- [ ] Index on `user_id` on every table with RLS on `user_id`
- [ ] Client queries include redundant `.eq('user_id', userId)` filters

### Tests (pgTAP under `supabase/tests/database/`)
- [ ] Owner SELECT positive
- [ ] Non-owner SELECT zero rows
- [ ] anon SELECT zero rows
- [ ] INSERT as own → succeeds
- [ ] INSERT with foreign user_id → WITH CHECK rejects
- [ ] UPDATE own → succeeds
- [ ] UPDATE to change user_id → WITH CHECK rejects
- [ ] UPDATE other user's row → USING denies
- [ ] DELETE own → succeeds
- [ ] DELETE other's → denies
- [ ] All tests use `SET LOCAL role authenticated; SET LOCAL request.jwt.claims ...` — never run as `postgres`
- [ ] All tests wrapped in `begin; ... rollback;`
